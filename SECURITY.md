# Security Policy

## Reporting a vulnerability

Do not publish exploit details, credentials, customer data, or proof-of-concept payloads in a public issue.

If GitHub private vulnerability reporting is available for this repository, use it. Otherwise contact the repository owner privately through GitHub and share only the minimum information needed to reproduce the issue safely.

Include the affected component, observed behavior, impact, reproduction preconditions, and a non-destructive verification path when possible.

## Scope

Project 8 handles tenant-separated business knowledge, conversations, and recovered-lead metadata. Anonymous visitor/session capabilities and domain allowlisting are not verified customer identity and must never be treated as authorization for private account data.

Security reports do not authorize testing against production, customer environments, third-party systems, or data without explicit permission.
